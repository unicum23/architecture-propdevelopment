
# Проверочный лист безопасности бизнес-систем PropDevelopment

---

## Обоснование выбора разделов проверочного листа

На основе анализа архитектуры системы PropDevelopment (диаграмма контейнеров) выявлены следующие приоритетные области безопасности:

### 1. Управление доступом — Высокий приоритет

- Система использует множественные точки входа (веб-витрина, мобильные приложения) и несколько систем аутентификации (Active Directory, Keycloak)
- Различные роли пользователей (клиенты, собственники, менеджеры, бухгалтеры, аналитики) требуют гранулярного разграничения прав
- Несколько точек регистрации клиентов при отсутствии единого реестра
- Проблемы с API партнёров, позволяющие доступ к чужим данным
- Высокие репутационные и финансовые риски при нарушении контроля доступа

### 2. Безопасность данных — Высокий приоритет

- Система обрабатывает персональные данные клиентов и собственников, платёжные данные, данные о сделках с недвижимостью
- Зафиксированы жалобы клиентов на отображение чужих данных в личных кабинетах
- Интеграция с внешними сервисами (платёжная система, поставщики ЖКХ, госорганы) требует защиты данных при передаче
- Централизованное хранилище данных (Greenplum, S3) требует контроля целостности и доступности
- Планы по внедрению BI/ML/AI требуют надёжной защиты данных и Data Governance
- Требуется соответствие 152-ФЗ

### 3. Защита инфраструктуры — Средний приоритет

- Гибридная инфраструктура (собственный ЦОД и облачные компоненты) требует дополнительных усилий по безопасности
- Система состоит из множества контейнеров и баз данных с внешними интеграциями через REST/SOAP/CDC
- На диаграмме присутствуют Firewall, но требуется проверка полноты сетевой защиты
- Недостаточная сегментация сети и мониторинг

### 4. Управление инцидентами — Средний приоритет

- Необходимо для оперативного реагирования на инциденты безопасности
- Особенно критично при обработке ПДн и платёжных данных
- Требуется соответствие требованиям 152-ФЗ в части уведомления об инцидентах

### 5. Специфические аспекты — Базовый приоритет

- Мобильные приложения, удалённый доступ, физическая безопасность
- Актуально для распределённой архитектуры с гибридной инфраструктурой

## Рекомендации по приоритетам внедрения мер безопасности

### 🔴 Критический приоритет (внедрить в первую очередь)

1. **Многофакторная аутентификация (MFA)** для привилегированных пользователей — менеджеров, бухгалтеров и администраторов, работающих с ПДн и платёжными данными (I.1)
2. **Шифрование данных** при передаче (TLS 1.2+, mTLS) и хранении (TDE для БД, SSE для S3) (II.2)
3. **Управление ключами шифрования** — внедрение HSM или KMS (HashiCorp Vault, AWS KMS) с регулярной ротацией ключей (II.3)
4. **Резервное копирование и восстановление** — автоматизация бэкапов всех БД, шифрование копий, ежеквартальное тестирование восстановления с фиксацией RTO/RPO (II.4, II.5)
5. **Реестр персональных данных** и процедуры их обработки в соответствии с требованиями 152-ФЗ — документирование целей обработки, сроков хранения, процедур удаления (II.7)
6. **SIEM-система и мониторинг безопасности** — централизованный сбор и корреляция событий из Active Directory, Keycloak, БД и Firewall с автоматическим оповещением об инцидентах (IV.1, IV.2)
7. **План реагирования на инциденты** — актуализация процедур для сценариев утечки ПДн, компрометации платёжных данных, DDoS-атак; определение ролей, порядка эскалации и регулярное проведение учений (IV.3)

### 🟠 Высокий приоритет

1. **Аудит привилегированных учётных записей** — ежеквартальный пересмотр ролей и прав администраторов в AD, Keycloak и БД (I.3)
2. **Автоматизация управления учётными записями** — автоматическая деактивация при увольнении или смене должности, интеграция с HR-системой (I.5)
3. **Централизованное журналирование** — единый аудит-лог операций доступа к ПДн и платёжным данным с ограниченным кругом лиц, имеющих доступ к журналам (I.6)
4. **DLP-система и мониторинг доступа к ПДн** — внедрение меток классификации данных, алертов на аномальный доступ к конфиденциальной информации (II.8)
5. **Регулярное сканирование уязвимостей** — ежемесячная проверка контейнеров, БД и сетевого оборудования с приоритетом на системы, обрабатывающие ПДн и платёжные данные (III.5)
6. **Системы обнаружения и предотвращения вторжений (IDS/IPS)** — расширение базовой IDS до полноценной IPS с охватом критических сетевых сегментов (III.3)

### 🟡 Средний приоритет

1. **Контроль доступа на основе атрибутов (ABAC)** — динамическое разграничение прав по УК, доменам и регионам для повышения гибкости управления доступом (I.7)
2. **Анонимизация данных** — псевдонимизация ПДн при копировании в тестовые окружения и передаче в DWH, использование синтетических данных для разработки (II.13)
3. **EDR на рабочих станциях и серверах** — внедрение Endpoint Detection and Response для всех узлов, обрабатывающих конфиденциальные данные (III.6)
4. **MDM для корпоративных устройств** — управление мобильными устройствами сотрудников, работающих с ПДн, контроль версий и целостности клиентских приложений (V.1.1)
