
# Требования к безопасности внешних интеграций сервисов «Умный дом»

---

## 1. Классификация данных

### 1.1. Конфиденциальные данные

- Персональные данные собственников и жильцов (ФИО, телефон, email)
- Биометрические данные (шаблоны лиц для распознавания)
- Номера автомобилей и привязка к собственникам
- Настройки доступа (разрешения на вход в дом / парковку)
- Идентификаторы объектов недвижимости и квартир

### 1.2. Секретные данные

- API-ключи и токены доступа к платформе партнёра
- Закрытые ключи для подписи запросов
- Учётные данные для аутентификации в системе партнёра

---

## 2. Аутентификация и авторизация

| Требование | Описание |
| :--------- | :------- |
| Протокол аутентификации | OAuth 2.0 с JWT-токенами; существующий Keycloak для взаимодействия между внутренними сервисами |
| Время жизни access token | Не более 15 минут |
| Управление секретами | API-ключи и токены хранить в защищённом хранилище (HashiCorp Vault, AWS Secrets Manager). Запрет хранения учётных данных в коде. Регулярная ротация ключей |
| Авторизация | RBAC с проверкой scope/roles для каждого API-эндпоинта. Проверка прав собственника в CRM перед каждым вызовом API партнёра |
| Принцип минимальных привилегий | Технические учётные записи (ТУЗ) с минимальным набором привилегий. Разграничение доступа по ЖК |

---

## 3. Защита данных

### 3.1. Шифрование при передаче

- **TLS 1.2+** для всех HTTP/HTTPS-соединений (рекомендуется TLS 1.3)
- **Perfect Forward Secrecy (PFS)** — использование эфемерных ключей
- **Certificate pinning** для мобильного приложения
- **Валидация сертификатов** сервера партнёра, регулярная ротация
- **Запрет устаревших протоколов**: SSL 3.0, TLS 1.0, TLS 1.1 отключены
- **WebSocket** (видеопоток с домофона) — только через WSS (WebSocket Secure)

### 3.2. Шифрование при хранении

- **Биометрические данные** — AES-256, хранение в зашифрованном виде
- **Номера автомобилей** — хранение хешей вместо оригинальных значений
- **Чувствительные поля в БД** — шифрование на уровне полей или TDE
- **Резервные копии** — обязательное шифрование

### 3.3. Минимизация и защита от утечек

- Передавать только необходимые атрибуты (принцип минимизации данных)
- Анонимизация видеопотоков после обработки
- Маскирование данных в логах: не логировать биометрию, полные номера автомобилей
- Соответствие требованиям 152-ФЗ при обработке биометрических данных и данных о ТС

---

## 4. Целостность данных и защита от атак

| Требование | Описание |
| :--------- | :------- |
| Цифровая подпись запросов | HMAC-SHA256 или RSA-SHA256 для всех запросов к API партнёра. Валидация подписи всех ответов |
| Защита от replay-атак | Nonce + timestamp в каждом запросе |
| Валидация источника | Firewall: whitelist по IP/домену и портам. Партнёр не имеет прямого доступа к CRM и БД — только через API-шлюз (smart-home-service) |
| Rate limiting | Ограничение частоты запросов для предотвращения злоупотреблений |

---

## 5. Архитектура взаимодействия

| Требование | Описание |
| :--------- | :------- |
| Единая точка входа | Все вызовы к партнёру — только через smart-home-service (device-app → smart-home-service → партнёр) |
| Формат данных | JSON over REST, контракт API описан в OpenAPI |
| Версионирование | Поддержка версионирования API и обратной совместимости |
| Обработка сбоев | Retry с экспоненциальной задержкой при 5xx-ошибках, circuit breaker при множественных отказах |
| Fallback | Резервные способы управления доступом при недоступности API партнёра |
| Буферизация | Очередь сообщений для буферизации событий при временной недоступности |

---

## 6. Доступность и SLA

| Параметр | Значение |
| :------- | :------- |
| Доступность API партнёра | ≥ 99.5% (uptime) |
| Среднее время отклика | ≤ 500 мс (p95 < 1 сек) |
| Максимальное время восстановления (RTO) | ≤ 4 часа |

---

## 7. Аудит и мониторинг

### 7.1. Логирование

- Централизованное логирование всех запросов к API партнёра
- Логирование всех операций с доступом (открытие двери / шлагбаума)
- Логирование успешных и неуспешных попыток распознавания
- Аудит изменений прав доступа и конфигураций
- Детальное логирование ошибок интеграции
- **Срок хранения логов** — не менее 90 дней

### 7.2. Мониторинг безопасности

- Обнаружение аномальных паттернов (множественные неудачные попытки доступа, подозрительная активность)
- Алерты о критических событиях безопасности в реальном времени
- Отслеживание метрик: количество запросов, ошибок, время отклика, ложные срабатывания распознавания
